# LinkShorteningService

![CI](https://github.com/Valipuz/LinkShorteningService/actions/workflows/ci.yml/badge.svg)

## Описание

Сервис сокращения ссылок – консольная программа, в которой пользователи могут создавать короткие ссылки на основе длинных URL и управлять ими.
Вся работа пользователя происходит в двух меню – Главном и Меню пользователя.
Для входа в Главное меню идентификация не требуется, пользователь получает возможность перейти в Меню пользователя или открыть короткую ссылку в браузере.
В Меню пользователя уже нужна идентификация по UUID для возможности создания коротких ссылок с выбором лимита переходов, дальнейшим просмотром своих ссылок, изменением и удалением.
Ссылки всегда получаются уникальными для всех пользователей и всех ресурсов.

## Функциональность

- **Сокращение ссылок.** Длинный URL (`http://` или `https://`) превращается в короткую ссылку вида `clck.ru/aB3xK9`. Один и тот же URL, сокращённый повторно или другим пользователем, получает новую уникальную ссылку.
- **Пользователи по UUID без авторизации.** UUID выдаётся при создании первой ссылки, по нему пользователь потом входит в Меню пользователя.
- **Лимит переходов.** Задаётся при создании (по умолчанию – из конфигурации), каждый переход засчитывается, после исчерпания лимита ссылка блокируется.
- **Время жизни ссылки (TTL).** Задаётся системой в конфигурации. Просроченная ссылка не открывается и автоматически удаляется фоновой очисткой.
- **Уведомления.** При переходе по ссылке с исчерпанным лимитом или истёкшим сроком пользователь получает сообщение с предложением создать новую ссылку.
- **Управление своими ссылками.** Просмотр списка со счётчиком переходов, изменение лимита и удаление. Изменять и удалять ссылку может только её владелец.
- **Открытие в браузере.** Введённая короткая ссылка открывается в браузере по умолчанию через `Desktop.getDesktop().browse(...)`. Если браузер недоступен, программа выводит исходный URL для перехода вручную.
- **Сохранение данных.** Пользователи и ссылки хранятся в JSON-файлах и не теряются после перезапуска.

## Требования

- **JDK 21** или новее.
- Maven устанавливать не нужно: в проекте есть Maven Wrapper (`mvnw` / `mvnw.cmd`), он сам скачает нужную версию Maven.

## Установка и запуск

Зависимости (Gson, JUnit 5) Maven скачивает автоматически при сборке

Клонировать репозиторий:

```bash
git clone https://github.com/Valipuz/LinkShorteningService.git
```

Перейти в директорию проекта
```bash
cd LinkShorteningService
```

Собрать проект (вместе с тестами):

```bash
./mvnw package
```

В папке `target/` появится исполняемый jar со всеми зависимостями – `link-shortening-service.jar`.

Если при запуске `./mvnw` появляется `Permission denied`, выполните `chmod +x mvnw` (бывает, если проект скачан ZIP-архивом).

Запустить программу:

```bash
java -jar target/link-shortening-service.jar
```

На Windows для сборки вместо `./mvnw` используется `mvnw.cmd`:

```bash
mvnw.cmd package
```

```bash
java -jar target/link-shortening-service.jar
```

jar можно скопировать в любую папку и запускать оттуда: конфигурация уже находится внутри jar.

Также программу можно запустить из IntelliJ IDEA: открыть проект как Maven-проект и запустить класс `org.valipuz.Main`.

При первом создании ссылки программа создаёт папку `data/` с файлами данных в каталоге, из которого запущена команда.

## Конфигурация

Все параметры задаются в файле `src/main/resources/application.properties`:

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `link.ttl.hours` | `24` | время жизни ссылки в часах |
| `link.limit.default` | `10` | лимит переходов, если пользователь его не указал |
| `link.limit.max` | `1000` | максимальный лимит, который можно задать |
| `link.code.length` | `6` | длина кода короткой ссылки |
| `link.domain` | `clck.ru` | домен, который подставляется в короткую ссылку |
| `cleanup.interval.minutes` | `60` | как часто запускать очистку просроченных ссылок |
| `storage.users.file` | `data/users.json` | файл с пользователями |
| `storage.links.file` | `data/links.json` | файл со ссылками |

После изменения конфигурации программу нужно перезапустить.

## Работа с программой

Управление – через меню: нужно ввести номер пункта и нажать Enter.

**Главное меню**

| Пункт | Действие |
|---|---|
| `1` | перейти в Меню пользователя (создание, изменение, удаление и просмотр своих ссылок) |
| `2` | ввести короткую ссылку и открыть её в браузере |
| `0` | выйти из программы |

**Меню пользователя**

При входе программа просит ввести UUID. Новый пользователь просто нажимает Enter – UUID будет выдан после создания первой ссылки.

| Пункт | Действие |
|---|---|
| `1` | создать короткую ссылку |
| `2` | изменить лимит переходов у своей ссылки |
| `3` | удалить свою ссылку |
| `4` | посмотреть свои ссылки |
| `5` | сменить пользователя |
| `6` | вернуться в Главное меню |
| `0` | выйти из программы |

Лимит ссылки `clck.ru/9yU0gS` из предыдущего примера – 3 перехода, все они уже использованы.

====== Главное меню ======

Введите короткую ссылку (пример: clck.ru/aB3xK9): clck.ru/9yU0gS

====== Главное меню ======

## Архитектура

### Структура проекта

```text
org.valipuz
├── Main.java                        # точка входа: читает конфиг, собирает зависимости, запускает очистку и меню
├── config
│   └── AppConfig.java               # чтение application.properties
├── controller                       # консольный интерфейс (CLI)
│   ├── MainMenu.java                # Главное меню, переход по короткой ссылке, открытие браузера
│   └── UserMenu.java                # Меню пользователя: вход по UUID, создание, изменение, удаление, список
├── entity
│   └── ShortLink.java               # модель короткой ссылки
├── exception
│   └── CustomException.java         # ошибки пользователя, которые меню показывает в консоли
├── repository                       # хранение данных
│   ├── LinkRepository.java          # интерфейс хранилища ссылок
│   ├── UserRepository.java          # интерфейс хранилища пользователей
│   └── impl
│       ├── LinkRepositoryImpl.java  # ссылки в data/links.json
│       └── UserRepositoryImpl.java  # пользователи в data/users.json
├── service                          # бизнес-логика
│   ├── LinkService.java             # создание, переход, лимиты, TTL, проверка владельца, очистка
│   └── UserService.java             # регистрация и вход по UUID
└── utils                            # вспомогательные классы
    ├── CodeGenerator.java           # генерация случайного кода ссылки
    ├── JsonFileHandler.java         # чтение и запись JSON-файлов
    └── Messages.java                # тексты сообщений об ошибках
```

Слои зависят только от нижележащих: `controller -> service -> repository`. Меню не обращаются к репозиториям напрямую, а сервисы ничего не знают о консоли.

`Main` – точка сборки приложения: читает конфигурацию, создаёт репозитории, сервисы и меню и передаёт зависимости через конструкторы (ручной DI). Ни один класс не создаёт свои зависимости сам, поэтому в тестах их легко подменить: временный файл вместо `data/`, фиксированные часы, генератор с заранее известными кодами.

### Принятые решения

- **Хранение – два JSON-файла** (`users.json` – множество UUID, `links.json` – список ссылок). Данные читаются один раз при запуске, хранятся в памяти (`LinkedHashMap` по коду ссылки) и при каждом изменении целиком перезаписываются в файл.
- **Код ссылки – её идентификатор.** Код уникален и не меняется, поэтому отдельный `id` не нужен.
- **Уникальность ссылок.** Код из 6 символов `[A-Za-z0-9]` генерируется через `SecureRandom` (62⁶ ≈ 56,8 млрд вариантов). Если код уже занят, генерируется новый, поэтому две ссылки с одинаковым кодом невозможны. Повторное сокращение того же URL создаёт новую ссылку со своим лимитом и сроком.
- **Регистрация после валидации.** Новый пользователь сохраняется только после того, как URL и лимит прошли проверку, поэтому при ошибке ввода не появляются пользователи без ссылок.
- **TTL проверяется в двух местах.** При переходе просроченная ссылка не открывается сразу, даже если очистка ещё не запускалась. Фоновая очистка (`ScheduledExecutorService`, первый запуск – сразу при старте) удаляет просроченные ссылки из файла. Методы `LinkService` помечены `synchronized`, потому что с данными работают два потока: консоль и очистка.
- **Время через `Clock`.** Сервис получает часы через конструктор, поэтому истечение срока проверяется в тестах без ожидания.
- **Уведомления получает тот, кто переходит по ссылке** – сообщением об исчерпанном лимите или истёкшем сроке с предложением создать новую ссылку.
- **Ссылка с исчерпанным лимитом остаётся в списке владельца** (например, `10/10`): владелец может увеличить лимит и снова сделать её рабочей. При изменении лимита счётчик переходов не сбрасывается.
- **Тексты ошибок собраны в классе `Messages`**, тесты сравнивают сообщения с этими же константами.

## Тестирование

Тесты написаны на JUnit 5 и запускаются командой:

```bash
./mvnw test
```

Всего 32 теста (с учётом параметризованных), unit и интеграционные:

| Класс | Тип | Что проверяется |
|---|---|---|
| `LinkServiceTest` | unit | создание ссылки с лимитом по умолчанию и с указанным лимитом; валидация URL и лимита; регистрация нового пользователя; уникальность ссылок для одного и для разных пользователей; подсчёт переходов и блокировка после лимита; переход по просроченной ссылке; очистка просроченных ссылок; изменение лимита владельцем без сброса счётчика; запрет изменения и удаления чужой ссылки; удаление владельцем; повторная генерация занятого кода |
| `UserServiceTest` | unit | вход по зарегистрированному UUID, по незарегистрированному UUID и по строке не в формате UUID |
| `CodeGeneratorTest` | unit | длина кода и допустимые символы, длина из параметра, разные коды при генерации |
| `LinkRepositoryImplTest` | интеграционный | ссылка и счётчик переходов сохраняются в JSON-файл и читаются после «перезапуска»; удалённая ссылка не возвращается |
| `MainMenuTest` | интеграционный | сценарии через консольное меню: создание ссылки новым пользователем и вывод списка, переход по ссылке до блокировки, обработка неверного ввода |

Приёмы, которые используются в тестах:

- **`@TempDir`** – каждый тест работает со своей временной папкой, реальные данные в `data/` не затрагиваются.
- **`Clock.fixed(...)`** – время «перематывается» вперёд, чтобы проверить истечение срока без ожидания.
- **Предсказуемый `CodeGenerator`** – подставляет заранее известные коды, чтобы проверить повторную генерацию занятого кода.
- **Интеграционные тесты меню** подают ввод через `new Scanner("...")` и перехватывают вывод `System.out`. Браузер в тестах не открывается (`java.awt.headless=true`).

## Качество кода и CI

- **Spotless** проверяет форматирование: неиспользуемые импорты, порядок импортов, пробелы в конце строк, отступы.
  - `./mvnw spotless:check` – проверить;
  - `./mvnw spotless:apply` – исправить автоматически.
- **`.editorconfig`** задаёт кодировку, отступы и переводы строк для редакторов.
- **GitHub Actions** (`.github/workflows/ci.yml`) при каждом push и pull request в `main` запускает проверку Spotless, сборку и все тесты (`./mvnw verify`).
